LOADLINK PHASE 2 — DEPLOYMENT STEPS

1. Keep a backup of the currently deployed website and database.

2. Open Supabase Dashboard > SQL Editor.
   Run the existing LoadLink SQL migrations first if the database has not
   already received them. Then run:

   LOADLINK-PHASE-2-FINAL.sql

   This final migration is additive. It does not intentionally delete users,
   listings or chat history.

3. Upload/commit the contents of this project folder to the same GitHub
   repository connected to Vercel. Do not upload the outer ZIP itself as the
   application root.

4. Confirm the existing Vercel environment variables remain present:
   - NEXT_PUBLIC_SUPABASE_URL
   - NEXT_PUBLIC_SUPABASE_ANON_KEY or NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY
   - Any existing LoadLink/OpenAI variables already used by this project

5. Trigger a fresh Vercel deployment from the new commit.

6. Test these internal routes after deployment:
   /
   /signup
   /jobs
   /trucks
   /messages
   /my-posts
   /account/settings
   /drivers
   /driver-profile
   /dealership/truckstore-centurion-demo
   /dealer-dashboard
   /dealer

7. Sign in with loadlinksouthafrica@gmail.com to test the dealership centre.

8. Functional checks:
   - Burger menu opens and all internal links stay on LoadLink.
   - Jobs show seven results per page.
   - Profile settings save and avatar upload works.
   - Driver profile saves, critical documents upload, and submission works.
   - A reviewed/approved driver appears in /drivers.
   - Voice notes record, send and play back.
   - Block/unblock prevents or restores messaging.
   - Demo dealership follow/tabs/details/pagination work.

The website code and SQL are separate deployment steps. Deploying only the ZIP
without running the SQL will leave database-backed Phase 2 features unavailable.
