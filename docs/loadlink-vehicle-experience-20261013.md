# LoadLink vehicle experience update

Backup: branch `backup/loadlink-before-vehicle-repair-20261013`, source commit `ab1ce1eaa53b8cfd5d1744edeff4b047da3dc0d9`. Previous production deployment `dpl_TEVWdz2To7aZZ8YybvPkAAUvq4YC` remains the website rollback target. Login behavior and branding are preserved.

The dealership public read previously returned `42501: permission denied for function loadlink_marketplace_is_restricted`. Its approved public view now evaluates the same restriction and subscription eligibility directly, without granting anonymous access to private helper RPCs. The view retains its existing public marketing fields, filtering and permissions, and adds a security barrier. The prior definition is saved under `supabase/rollback/20261013_dealership_public_directory_read.sql`. No subscription or user record is changed. Directory requests have bounded timeouts, normalization, retry and route error boundaries. An empty directory is shown when no approved public profiles are eligible.

The global vehicle wizard and reference overlay have been removed. The listing page owns its controls. Account-scoped drafts save on navigation and offer continue/start-fresh on the next login. Successful submission and explicit cancellation clear both active and stored account drafts. Uploaded files are not stored in device draft storage and must be selected again.

Calls retain the existing WebRTC and chat-history behavior, with circular controls, compact typography, theme colors and a timer that appears after connection. Vehicle portal actions are pills. The initial listing choice is smaller and direct. Toast surfaces retain their layout with consistent theme foreground, background and detail colors.

Image delivery preserves component geometry while adding responsive optimization, early hero loading, caching and an original-source fallback. Private signed URLs are never routed through the public image optimizer. Missing images receive a neutral placeholder rather than an unrelated truck. The curated photograph proxy accepts only catalog IDs and approved Wikimedia hosts, bounds image type/bytes/timeouts, and uses same-photo thumbnails.

The isolated reference table has 242 model families, 241 sourced photographs and 64 local photographs. Their checked binary data is versioned in photograph packs and materialized into public assets during prebuild; this avoids runtime image downloads for these models. FAW Tiger V Plus remains without a photograph because its identity could not be verified. Model-family images and their source, photographer, license and generation captions are retained. Photographer capture dates do not imply generation validity. Manufacturer/editorial rights are explicitly recorded as permission not stated where no reuse license is given. No generated imagery is included. Unknown or multi-variant mechanics remain editable; only supported defaults fill automatically. Rebuild the versioned snapshot with `node scripts/build-truck-model-catalog.cjs` after verified research changes.

The catalog has RLS with public SELECT and no anonymous/account write privileges. The earlier billing migration in PR36 remains unapplied; the current R15 active-day pricing contract is preserved.

Validation: TypeScript, production build and regression tests cover call history, pricing, draft account isolation/logout/login/storage failure, malformed directory rows, reference identity/default provenance/year boundaries, off-route wizard rendering, image geometry/private URLs and photo endpoint validation. Deployed HTTP checks cover dealership reads and image delivery. Browser visual interaction and two-account microphone calls cannot be tested in this managed environment; an actual phone call remains a device-level verification limit.
